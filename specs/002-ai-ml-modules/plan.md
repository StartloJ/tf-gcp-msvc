# Implementation Plan: AI/ML Platform Shared Modules

**Branch**: `002-ai-ml-modules` | **Date**: 2026-07-08 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-ai-ml-modules/spec.md`

## Summary

Develop 13 new reusable Terraform modules across 6 new module categories to support GCP AI/ML platform workloads. Modules follow the same interface contract (labels, project_id, region, naming tokens) as the existing 9 modules. Two architectural decisions resolved during planning: (1) Private Service Connect uses a single generic consumer-endpoint module fed by service attachment URIs output from each service module; (2) Enterprise network egress is managed via GCP Secure Web Proxy (not a simple NAT extension).

## Technical Context

**Language/Version**: HCL (Terraform >= 1.12)

**Primary Dependencies**:
- `hashicorp/google >= 7.10, < 8`
- `hashicorp/google-beta >= 7.10, < 8`
- `hashicorp/random ~> 3.9`

**Storage**: Remote state (GCS backend) — not in scope for module development; modules use local/mock state during unit tests.

**Testing**: Terraform 1.12 test framework (`.tftest.hcl`) with `mock_provider "google" {}` — same pattern as existing modules.

**Target Platform**: GCP (asia-southeast1 primary, asia-southeast1 DR region for Singapore replication)

**Project Type**: Terraform IaC module library

**Performance Goals**: All module unit tests complete in < 60 seconds each; `./tests/run-unit-tests.sh` completes in < 10 minutes total for all 22 modules (9 existing + 13 new).

**Constraints**:
- Every module MUST pass `pre-commit run --all-files` (terraform-fmt, tflint, terraform-docs-go).
- No `any`-typed variables (constitution Principle II).
- KMS key rings and crypto keys MUST have `prevent_destroy = true` by default.
- Cloud Run in `prd` environment MUST NOT allow unauthenticated access.
- Secret plaintext MUST NOT appear in any module output.

**Scale/Scope**: 13 new modules, ~6 new module categories, ~2,000 lines of new HCL across modules + unit tests.

## Complexity Tracking

No constitution violations requiring justification.

| Decision | Rationale |
|---|---|
| Generic PSC module (not per-service) | PSC consumer endpoint pattern is identical across all GCP services — only `service_attachment_uri` differs. One module handles all cases without duplicating 13 forwarding-rule blocks. |
| Secure Web Proxy for egress | Cloud NAT only provides IP masquerading (no content inspection). SWP provides URL-level HTTP/HTTPS policy enforcement — the enterprise-appropriate choice for AI/ML workloads calling external APIs. |
| DR via variables, not separate modules | DR Storage (GCS replication) and DR Compute (Dataproc standby) are parameterised features of the GCS and Dataproc modules respectively. No DR-specific modules needed. |
| Artifact Registry not duplicated | Existing `modules/workload/artifact-registry` already supports `format = "DOCKER"` for model storage. An additional AI-specific module would be redundant. |
