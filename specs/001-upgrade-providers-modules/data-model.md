## Entity 1: `versions.tf` Constraint File

Exists in every module directory, every stack directory, and every example directory.
Defines what versions of Terraform and each provider are accepted for that code unit.

**Fields**:

| Field | Type | Constraint |
|---|---|---|
| `required_version` | string (semver constraint) | MUST be `>= 1.12` across all files |
| `required_providers.<name>.source` | string | `hashicorp/<name>` — unchanged |
| `required_providers.<name>.version` | string (semver constraint) | See version matrix |
| `provider_meta.<name>.module_name` | string | Updated after upstream module version change |

**Target version matrix** (all files after upgrade):

| Provider | Constraint | Applies to |
|---|---|---|
| `hashicorp/google` | `>= 7.10, < 8` | All modules, stacks, examples |
| `hashicorp/google-beta` | `>= 7.10, < 8` | Modules/stacks that use beta resources |
| `hashicorp/random` | `~> 3.9` | `router-nat`, `vpn-classic`, `vpn-ha`, `sql/postgresql` |
| `hashicorp/null` | `~> 3.3` | `sql/postgresql` |
| `hashicorp/kubernetes` | `~> 3.2` | `stacks/example` only |
| `hashicorp/helm` | `~> 3.2` | `stacks/example` only |
| `hashicorp/http` | `~> 3.6` | `stacks/example` only |

## Entity 2: `.terraform.lock.hcl`

Exists in `stacks/example/` (the only stack with committed lock file).
Records the exact provider versions and checksums that `terraform init` resolved.

**Fields**:

| Field | Description |
|---|---|
| `provider "registry.terraform.io/hashicorp/*"` | One block per provider |
| `version` | Exact resolved version (e.g., `6.14.0`) |
| `constraints` | The constraint string from `versions.tf` |
| `hashes` | SHA256 hashes of provider binaries per platform |

**State after upgrade**: Regenerated by `terraform init -upgrade` in `stacks/example/`.
Must be committed to VCS so all team members use the same resolved versions.

## Entity 4: Module Test File (`.tftest.hcl`)

New entity — one per module. Created as part of the integration test work.
Uses Terraform 1.9 native test runner.

**Fields**:

| Field | Description |
|---|---|
| `mock_provider "<name>"` | Declares a mock for a provider; no real API calls |
| `mock_resource "<resource_type>"` | Defines default field values for a mocked resource |
| `run "<name>"` | One test case; contains `command = plan` or `command = apply` |
| `assert { condition }` | A single boolean expression that must be true to pass |

**File location per module**:

```
modules/<category>/<name>/
└── tests/
    └── unit.tftest.hcl    # mock-provider unit test
```

**File location for stack integration tests**:

```
stacks/example/
└── tests/
    ├── unit.tftest.hcl        # mock provider tests for stack-level logic
    └── integration.tftest.hcl # tests run against docker-compose emulator stack
```

## Entity 5: docker-compose Integration Stack

New entity — lives at `tests/local-gcp-stack/docker-compose.yml`.
Provides GCP service emulators for integration testing.

**Services**:

| Service name | Image | Port | Purpose |
|---|---|---|---|
| `fake-gcs` | `fsouza/fake-gcs-server:1.49` | 4443 | Simulate GCS for Terraform state backend |
| `postgres` | `postgres:16-alpine` | 5432 | Simulate Cloud SQL PostgreSQL |
| `local-registry` | `registry:2` | 5000 | Simulate Artifact Registry |

**Environment variables for Terraform** (set in test runner script):

| Variable | Value | Effect |
|---|---|---|
| `STORAGE_EMULATOR_HOST` | `http://localhost:4443` | Google provider redirects GCS calls to fake-gcs |
| `CLOUDSDK_CORE_PROJECT` | `test-project` | GCP project name for tests |
| `GOOGLE_OAUTH_ACCESS_TOKEN` | `fake-token` | Bypass OAuth for provider init |

**Files**:

```
tests/local-gcp-stack/
├── docker-compose.yml     # service definitions
├── init.sh                # start stack, wait for health, export env vars
└── teardown.sh            # stop and remove containers
```
